## This AGY pass: layout and key plumbing

The bounded changes are the metric grid minimum extent, `_TodayDateBadge` intrinsic height, productivity score circle sizing plus `FittedBox`, and constructor key forwarding for retained child widgets. No blocking finding in these edits by static inspection.

- `metricsGrid` (`today_screen.dart:165-313`) now always supplies a `mainAxisExtent` that is the maximum of its natural aspect-ratio height and a text-scale-aware content minimum. The calculation matches `AppMetricCard`'s 10/12 px vertical padding, 28/32 px icon, one-line title, 2 px gap, and one-line value. The card itself clips both text lines with ellipsis, so the calculated height protects vertical layout while narrow labels may still truncate. `GridView.count` accepts `mainAxisExtent` together with `childAspectRatio`; the explicit extent wins.
- `_TodayDateBadge` (`:1467-1549`) replaces fixed `height: 76` with `minHeight: 76`, allowing its month/year text to grow; the day number is still constrained to a 44×31 box and scales down inside it. Its parent Row can grow with the badge.
- `_TodayProductivityCard` (`:1712-1859`) scales the circular score area with `MediaQuery.textScalerOf` and scales down its internal number/label when necessary. The rest of the card has an unconstrained vertical extent and a flexible text column, so it can grow as text wraps. The calculated circle is unbounded at very large accessibility scales; the named 1.6× candidate test range is within a usable width at 320 px. No claim is made for arbitrary scales.
- `_TodayTodoSwipeTile` and `_SuggestionSection` now accept forwarded keys (`:2448,3406`), matching keyed construction sites in the earlier draft. The swipe tile resets its open state when its Todo ID changes (`:2470-2484`). The top-level `TodayScreen({super.key})` already exists in HEAD; it is not a new diff against HEAD.

## Earlier locale/account draft in the same working diff

`TodayScreen` wraps its content in `ValueListenableBuilder<AppLocale>` (`:79-581`) while keeping Provider watches in the parent build. A locale notification recomputes the brand greeting, date/almanac display, summaries, reminders, and actions; Provider notifications still rebuild the parent. The mobile list retains its `today_screen_list` key, and the stateful reminder/suggestion children keep their type and position, so locale rebuilds should preserve scroll/expanded state. The added Today smoke tests exercise a notifier-only greeting change and expanded reminders plus scroll retention (`today_mine_smoke_test.dart:119-221`).

The helpers translate app-generated text while leaving authored Todo titles, course name/location/teacher, goal/anniversary titles, list names, and username literals in the UI. `TodayUiCopy.formatSuggestionReason` translates tokens produced by `SmartScheduleAdvisor`, which constructs its reasons from fixed app strings; unknown tokens are returned literally. `AlmanacLocaleFormat` formats generated lunar dates, solar terms, festivals, and Yi/Ji activities, returning unknown terms literally. Chinese output for the activity preview retains the original up-to-four whitespace-delimited terms and ellipsis. The existing `rawUsername == '用户'` fallback still treats an authored identical username as generated; that comparison is present in HEAD, outside this draft.

The new delete confirmation captures the Todo ID, title, and `AccountLocalDataCleaner.accountDataGeneration` before opening the dialog (`today_screen.dart:2510-2541`). Its locale listener rerenders only app copy, while the captured title remains literal. After confirmation it requires the widget to remain mounted, the account generation to match, and the Todo ID still to match before calling the provider. The new smoke test switches account data and locale while the dialog is open, then confirms that the new account Todo is untouched (`today_mine_smoke_test.dart:149-194`). The separate completion flow already carries an origin account generation (`lib/widgets/todo_completion_flow.dart:15-94`).

**Residual account-switch issue, predating this AGY pass:** the Today suggestion `onAddToday` callback (`today_screen.dart:359-371`) sends only `todo.id` to `TodoProvider.scheduleTodoForToday` and has no account-generation check before/after its await. In `lib/providers/todo_provider.dart:1500-1510`, `_scheduleTodoForTodayLocked` awaits `_ensureStorageLoaded()` and then looks up that ID without checking the generation captured when the action started. If an account switch occurs while loading and the next account contains the same Todo ID, the old action can schedule the new account's item; a successful old action can also show a stale snackbar after the switch. This call path already exists in HEAD. It is a blocking edge **for an account-switch safety claim about the whole Today surface**, though it is not caused by AGY's layout edits. Fixing it requires a generation check in the provider after the await and a generation check around Today feedback; guarding only the dialog does not cover this path.
