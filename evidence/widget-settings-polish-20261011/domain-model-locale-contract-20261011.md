# Domain model locale contract — 2026-10-11

Read-only source audit. No source or tests were changed or run. Scope: model-generated display text, its storage/export/widget consumers, and the boundary between localized presentation and stable data.

## P1 — Diary labels and generated titles cross three different contracts

`Mood.label` and `Weather.label` are fixed Chinese getters, while `DiaryEntry.title` generates `M月D日的日记` for empty content (`lib/models/diary_entry.dart:14-45,92-97`). The model's persisted JSON uses **enum indices**, content, dates, tags, and paths; it does not persist these labels or the derived title (`:103-127`). Preserve enum order and index mapping, `dateKey`, authored content and tags. A locale switch must change only generated presentation, never `toJson()` or a user's first content line.

The same getters feed different sinks:

| Sink | Current path | Contract |
| --- | --- | --- |
| Diary UI | `lib/screens/diary_screen.dart:538-565,670-686,819-873` | Mood/weather choices already use `I18n.tr('diary.mood.*' / 'diary.weather.*')`; empty `entry.title` remains Chinese. Reuse those existing keys for generated model display. |
| Calendar | `lib/core/calendar_aggregator.dart:350-369` | `CalendarEvent.title` snapshots `d.title`; `subtitle` snapshots `d.mood?.label`, but `DiaryDisplayMetadata.moodKey` lets `CalendarEventDisplayText.resolveSubtitle()` render the mood live (`lib/core/calendar_event_display_text.dart:80-84`). An empty diary title has no equivalent fallback marker: add typed date/fallback provenance or rebuild events on locale change. Preserve authored title and custom event subtitles. |
| Search | `lib/core/global_search.dart:130-153` | `SearchHit.title` snapshots `DiaryEntry.title` and `NoteItem.title`; refresh those derived hits on locale change or carry fallback provenance. Query matching remains on authored content/tags. |
| Home widget | `lib/main.dart:467-492,2942-2950`; `lib/services/home_widget_service.dart:631-681` | Note and diary highlights are rendered strings in a persisted widget payload. `main.dart:240` includes `I18n.current.name` in its data signature and `:2601-2606` queues a push on locale change, so resolve generated titles at push time; preserve IDs and authored text. Empty widget placeholders already use localized `I18n.tr` copy. |
| CSV | `lib/services/ics_exporter.dart:192-207` | `ModuleExporter.diaryCsv` writes `mood.label,weather.label`. Existing `test/services/module_exporter_csv_static_test.dart:282-319` asserts all CSV exports are identical across locales and includes `开心,晴`. If `.label` becomes live-locale, this exporter must use explicit stable legacy Chinese labels (or a separately versioned schema); keep header, column order, enum codes, and historical output stable. `notesCsv` also exports `n.title` (`:174-186`), so an empty-note fallback must remain stable there. |
| AI review | `lib/core/diary_deep_review.dart:35-75`; `lib/services/ai_service.dart:477-490` | The current prompt is explicitly Chinese and interpolates mood/weather labels; its summary becomes an `AiReviewEntry` history value. Use an explicit Chinese label for this prompt until the whole prompt/output contract is deliberately localized. Do not silently mix English labels into a Chinese prompt or rewrite already generated history. |

Use an explicit locale-aware presentation method such as `labelFor(AppLocale)` and a current-locale `label` getter, with a separate stable `legacyCsvLabel` where needed. `DiaryEntry.title` should keep the authored first line literally and localize only its empty-content fallback. Do not guess that Chinese content is generated copy. Emoji remain language-independent.

`NoteItem.title` has the same authored-first-line/Chinese-empty-fallback split (`lib/models/note.dart:185-189`). It feeds note UI/search, `main.dart` widget snapshots, `ModuleExporter.notesCsv`, and `notesMarkdown` (`lib/services/ics_exporter.dart:174-186,275-299`). Localize its empty display title lazily, but keep CSV historical output stable. A Markdown export may use locale-aware generated headings while preserving authored note body and attachment names. Default attachment/name values loaded from sparse JSON (`note.dart:29-35`) are stored data fallbacks, not automatically safe to relabel retroactively.

## P2 — Other generated model labels and summaries

- **Workspace:** `WorkspaceRole.label` and `WorkspaceActivity.label` are fixed Chinese (`lib/models/workspace.dart:1-13,278-288`) and are displayed in share and goal-edit surfaces. Render them from current locale, while keeping `role.name` and action strings as wire codes (`workspace.dart:33-45,291-305`). Unknown activity actions must remain literal; member names, workspace names, comments, and activity detail are authored/server data. Sparse-JSON fallback workspace names (`:109,218`) may become stored values, so they require provenance or a separate migration before localization. Relevant tests: `test/models/workspace_permission_test.dart`, `test/services/share_collaboration_static_test.dart`.
- **Habit:** `HabitFlexProgress.labelPrefix` / `.label`, `Habit.flexPeriodGoalLabel`, and `Habit.formatCountForDate()` generate Chinese period/unit framing (`lib/models/habit.dart:135-140,476-481,625-633`). They reach habit cards and calendar event subtitles (`lib/widgets/habit_weekly_card.dart:576`, `lib/core/calendar_aggregator.dart:201`). Render app-owned week/month/recorded/default-unit copy live; preserve user-authored `unit` and serialized flex period/target. `streakUnitLabel` already uses `I18n.tr` (`habit.dart:468-474`). Cached calendar habit subtitles need rebuild or typed metadata. Existing targets: `test/models/habit_json_safety_test.dart`, `test/providers/habit_provider_test.dart`.
- **Focus rankings:** `FocusSocialRanking.title/subtitle` are generated getters (`lib/models/focus_room.dart:169-177`), safe to localize from `scope` at read time. Local anti-cheat `flagReason` strings are built and stored in ranking entries (`:388,436-447`), so a locale switch does not rerender them; carry typed local reasons or recompute ranking. The provider also supplies remote `riskSummary` as `flagReason` (`lib/providers/focus_room_provider.dart:1195,1243`): preserve that server text literally rather than translating all `flagReason` strings. Default `currentUserName = '我'` and sparse-JSON room/member name fallbacks (`focus_room.dart:28,65,192,279`) need explicit provenance if changed. Existing target: `test/models/focus_room_test.dart`.
- **Pomodoro penalty reasons:** `FocusPenaltyReason.label` is fixed Chinese and used by the penalty UI (`lib/models/pomodoro.dart:180-193`; `lib/screens/pomodoro_screen.dart:2037`). `PomodoroFocusPenalty.toJson()` also writes `reasonLabel: reason.label` alongside stable `reason: reason.key` (`pomodoro.dart:225-230`), and tests assert the Chinese JSON field (`test/models/pomodoro_config_test.dart:165-186`). If UI `.label` becomes localized, keep `reason` keys and the legacy `reasonLabel` serialization stable (or migrate/version it explicitly). Do not let a locale switch change persisted penalty payloads.

## Lower-priority data-default boundary

Several model `fromJson` fallbacks create real data strings, including `Habit.name = 未命名习惯` (`lib/models/habit.dart:388`), `FocusRoom.name = 专注自习室` and member `name = 同学` (`lib/models/focus_room.dart:28,65`), `Workspace.name = 共享空间` (`lib/models/workspace.dart:109,218`), `NoteAttachment.name = 附件` (`lib/models/note.dart:33`), and `LocationReminder.title = 位置提醒` (`lib/models/location_reminder.dart:118`). These may be serialized or synchronized after loading. Treat them as compatibility data until a typed missing-value marker or migration distinguishes a generated fallback from an authored identical string. Do not translate arbitrary stored text by content matching.

## Acceptance targets

1. Chinese ↔ English changes diary mood/weather labels and empty diary/note display titles without changing enum indices, serialized content, authored first lines, IDs, or widget deep links. Calendar and widget snapshots refresh generated text in the selected locale.
2. `ModuleExporter.diaryCsv` and `notesCsv` stay byte-identical across locales, including legacy Chinese mood/weather and empty-note fallback; headers and columns stay fixed. `test/services/module_exporter_csv_static_test.dart` is the existing invariant.
3. The Chinese AI diary review prompt remains internally consistent and persisted history remains untouched after locale changes; a future bilingual AI flow must select its prompt language explicitly before request creation.
4. Workspace role/activity display and habit/focus/pomodoro generated copy follow live locale, while wire role/action/reason keys, user/server strings, and legacy penalty JSON fields stay stable. Existing model tests above should be extended with both-locale and serialization assertions.

## P1 production diff review — 2026-10-11

Read-only review of `diary_note_ui_copy.dart`, the diary/note models, the AI prompt, exports, calendar event/aggregator/display resolver, and global search. No source or tests were changed or run for this review. **No blocking defect found in this bounded diff.**

The fallback is based on `content.trim().isEmpty`, never comparison with a Chinese title. Mood/weather enum order and JSON index mapping, diary/note JSON fields, IDs, tags, and authored content are unchanged (`lib/models/diary_entry.dart`; `lib/models/note.dart`). The new English mood/weather strings match the existing diary UI translation keys in `lib/core/i18n.dart:1928-1940`.

Markdown headings use the export's selected locale, with authored note content unchanged (`:275-299`).
- The aggregator attaches `DiaryDisplayMetadata` if there is a mood or generated empty title, including an empty diary with no mood. The nullable mood key and fallback date are independent; the resolver localizes only marked titles and mood subtitles, returning raw event text otherwise (`lib/core/calendar_aggregator.dart:350-375`; `lib/models/calendar_event.dart:263-268`; `lib/core/calendar_event_display_text.dart:13-26,80-89`). `CalendarEvent.title`, constructor, `copyWith`, and JSON serialization remain raw, so the separate data-path risks in the cached-title follow-up are avoided.

The const constructor, source IDs, and navigation dates are unchanged.

Frontend completion remains separate: calendar compact/day/week rows still read raw `CalendarEvent.title`, and `SearchScreen` must repaint its retained hits on locale changes. These are recorded in [cached-title follow-up](domain-cached-title-audit-20261011.md). The present review does not claim those screens are finished.
