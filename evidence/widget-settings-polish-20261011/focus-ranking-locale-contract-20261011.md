# Focus ranking locale contract — 2026-10-11

Read-only bounded decision audit of `lib/models/focus_room.dart` and `lib/providers/focus_room_provider.dart`. No implementation or tests were changed or run.

## Source boundary

`FocusSocialRanking.title` and `.subtitle` are generated solely from `FocusLeaderboardScope` (`lib/models/focus_room.dart:148-178`). They can safely become `titleFor(AppLocale)` / `subtitleFor(AppLocale)` with current-locale getters. No title or subtitle is stored in room JSON.

`FocusRoomRankingEntry.flagReason` has two origins. Local scoring writes four app-owned Chinese reasons: a seed member over the weekly cap (`focus_room.dart:379-390`), plus a session over four hours, a day over twelve hours, and a future session (`:394-450`). The latter three can coexist and are joined in that fixed order with `；`. Both room and social ranking builders copy the score into final ranked entries (`:188-267,274-359`). By contrast, remote room/social builders copy the server's nonempty `riskSummary.trim()` into `flagReason` (`lib/providers/focus_room_provider.dart:1176-1257`). A remote reason must remain literal even when it happens to equal a local Chinese phrase. The provider also generates its own fallback `服务端已校正异常时长` when a remote entry is flagged but has no summary; that fallback is app copy, not server text.

## Minimum compatible representation

Add a typed, optional provenance field to `FocusRoomRankingEntry`, for example `List<FocusFlagReasonCode> generatedFlagReasons = const []`, with codes `weeklyCap`, `longSessionCap`, `dailyCap`, `futureSessionIgnored`, and `remoteCorrectionFallback`. Preserve the public named constructor argument `flagReason`: receive it as `String? flagReason`, store it privately as `_flagReason`, and expose `String? get flagReason => flagReasonFor(I18n.current)`. `flagReasonFor(locale)` renders a nonempty code list in its existing order, joined with the locale's separator; with no codes, it returns `_flagReason` verbatim. This retains const construction and existing call sites. It does not translate by comparing string contents.

Create codes where reasons originate, not when a row paints. Local score objects may keep their legacy Chinese `flagReason` for compatibility, but should also carry codes. Pass those codes into the first ranking entries **and through the rank-assignment copy loops** in both local builders; otherwise the final entries freeze the Chinese string again. For remote entries, set codes only for the empty-summary app fallback. If `riskSummary.trim()` is nonempty, leave codes empty and pass that literal string through. In particular, neither `riskFlags` nor `flagged` alone identifies a translation key for a server explanation.

This adds display provenance only. Keep `flagged`, credited/raw seconds, session counts, tie breakers, rank, `suspiciousEntryCount`, and `FocusRoom`/seed JSON exactly as they are. `FocusRoomRankingEntry` and `FocusSocialRanking` currently have no `toJson`/`fromJson`; the provider's stored room payload contains rooms, memberships, and active room ID, not these reason strings (`focus_room_provider.dart:1084-1096`). No data migration is needed for the in-memory ranking values.

## Repaint and acceptance boundary

The Pomodoro screen has a locale listener (`lib/screens/pomodoro_screen.dart:445-465`), but its ranking sections use `Selector` view models whose equality/signatures read `entry.flagReason` (`:2962-3013,3030-3047,3301-3349`). If the same cached remote or local ranking object is compared on a locale switch, both old and new signatures can read the **new** live getter and compare equal. Make locale an explicit selector/view-model input, or place a locale listenable builder at the rendered ranking section, so cached entries actually repaint. This is a UI follow-up, not a reason to rebuild scores or refetch remote rankings.

Acceptance cases for the implementing owner: Chinese and English `FocusSocialRanking` headings change from the same object; a cached local multi-reason entry changes language while retaining reason order and numeric scores; a capped seed member displays the weekly-cap reason in both languages; a remote nonempty `riskSummary` remains byte-for-byte literal across locale changes (including one equal to a local phrase); a flagged remote entry with empty summary uses the localized app fallback. Existing assertions in `test/models/focus_room_test.dart:81-145` cover Chinese scoring/order and should remain true.

## Actual P2 diff review — 2026-10-11

Read-only review of the current diff in `lib/models/workspace.dart`, `lib/models/pomodoro.dart`, `lib/models/focus_room.dart`, and `lib/providers/focus_room_provider.dart`. No source or tests were changed or run for this review. **No blocking defect found in these four files.**

The focus implementation uses an immutable `int generatedFlagReasons` bitmask derived from `FocusFlagReasonCode.mask` instead of the example `List` above. It preserves the const named `flagReason` constructor, stores literal text separately, and renders nonzero codes in enum order. The enum order retains the old local explanation sequence: weekly cap for seeds; long-session cap, daily cap, then ignored future records for session scoring. Both initial entries and the final rank-copy loops propagate the mask for room and social rankings (`focus_room.dart:269-320,357-412`). The credited/raw seconds, session count, flags, sorting/tie breakers, rank, and suspicious-entry count calculations are unchanged. New provenance is runtime-only; room and seed JSON are unchanged.

Both provider remote builders still trim and pass through every nonempty `riskSummary`; those entries receive a zero mask, including summaries equal to a local Chinese phrase. Only a flagged entry with an empty summary gets the typed `remoteCorrectionFallback` bit (`focus_room_provider.dart:1176-1264`). Thus the app fallback follows locale without translating server text by content. A cached entry's `flagReasonFor(locale)` and a cached `FocusSocialRanking`'s `titleFor`/`subtitleFor` can render either locale without rescoring or refetching. The Pomodoro screen's `Selector` repaint gap described above remains; this model diff alone does not close it.

Workspace role and activity getters now use explicit-locale methods while preserving role enum order, permissions, `role.name` wire values, action codes, unknown actions, actor/detail text, and workspace JSON (`workspace.dart:1-24,30-129,263-310`). Penalty labels are live, while `PomodoroFocusPenalty.toJson()` explicitly writes the legacy Chinese `reasonLabel` and unchanged stable `reason` key (`pomodoro.dart:166-245`). The separately completed workspace/penalty regression reports **18 tests passed** and **four-file analysis clean** in [workspace and penalty locale regression](workspace-penalty-locale-regression-20261011.md).
