The missing UI reads are in `calendar_day_agenda.dart`: compact title at line 675, regular title at 744, regular subtitle presence/text at 778-782, and the subtitle-dependent regular-height estimate at 583. `calendar_week_strip.dart` reads raw subtitle for its combined time/detail at 421 and raw title at 468. Use one resolved subtitle per row build for both presence/layout and text. Keep `CalendarWeekStrip._compareEvents` at 227-233 on raw title so locale changes do not reorder equal-time events. Keep event objects, IDs, navigation, drag, and sheet behavior unchanged; the calendar page already listens to locale changes.

**What current tests miss:** `test/core/calendar_event_display_text_test.dart` proves cached object resolution, authored/literal preservation, and unchanged serialization, but never mounts the day or week rows. `test/screens/calendar_content_locale_state_test.dart` exercises a mounted calendar across locales with literal Todo titles and page framing; those titles cannot reveal a raw generated-title read. `test/widgets/calendar_day_timeline_static_test.dart` checks structure and layout source strings, not resolved text or subtitle-driven height.

**Small retained transition:** Build one Calendar event collection in Chinese with a generated Pomodoro fallback title and duration subtitle, an empty-diary fallback title or generated Habit subtitle, and one authored/imported literal event. Keep the same event objects and selected day mounted; switch `I18n` to English and pump without rebuilding the provider collection. Assert authored/imported strings, event order, IDs, and raw `event.title`/`event.subtitle` snapshots stay unchanged. A subtitle-presence/layout case should use a metadata-derived subtitle with raw subtitle absent or different, so the regular-height path is actually exercised.

## G. Search retained results

`SearchScreen` holds `_hits` and `_query` in state (`search_screen.dart:37-40`). `GlobalSearch.run` executes from the debounced text callback at 60-89, while `_resultCard` reads the live `SearchHit.title` getter at 275. The screen has no locale subscription in `initState`/`dispose` at 43-53, so a mounted result can stay in its old rendered language until an unrelated rebuild. Add a locale listener that only schedules a repaint and remove it on disposal. Do not invoke `_onChanged` or `GlobalSearch.run` on locale changes; query text, result membership/order, highlight query, source IDs, and dates remain the existing snapshot.

**What current tests miss:** `test/core/global_search_time_entry_test.dart` proves a retained `SearchHit` getter changes for a tag-matched empty diary and proves query membership excludes generated fallback titles. `test/screens/search_screen_static_test.dart` checks source wiring and navigation strings. Neither mounts `SearchScreen` with results, changes locale, or catches a missing listener. An empty note with truly blank content cannot be reached by a nonempty query through `GlobalSearch.run`; its typed fallback is covered at the model level and should not be forced into a new search rule for this UI check.

**Small retained transition:** Mount Search in Chinese with a blank-content diary tagged `review` and an authored diary also tagged `review` whose literal first line matches the Chinese fallback. Enter `review`, let the 180 ms debounce complete, and record the displayed query, result count/order, IDs and date. Switch to English without editing the field or notifying providers. The same result row should change from `10月11日的日记` to `Diary for 10/11`, while the authored literal stays Chinese and the `review` query, count/order, highlight behavior, and route target stay the same. Switch back once; after removing the screen, a further locale change should cause no disposed-state error.

## H. Pomodoro cached ranking selectors

The model now has typed generated `flagReason` provenance and live `FocusSocialRanking.title`/`subtitle` getters (`focus_room.dart:153-156,217-237`). The Pomodoro page listens to locale at 446-465, but both ranking sections are nested `Selector`s (`pomodoro_screen.dart:2964,3062`). Their view-model equality recomputes signatures on stored ranking objects (`:3032-3045,3146-3160`), and `_focusRankingEntriesSignature` reads the live `entry.flagReason` at 3347. On a locale switch, both the old and new view models can evaluate that same cached object in the *new* locale and compare equal. Give both selector view models an immutable locale input included in equality/hash, or put an explicit locale-listenable builder around each ranking section. Do not refetch or rescore merely to repaint.

**What current tests miss:** `test/models/focus_room_test.dart` checks cached local reasons, headings, scores, and literal remote reasons across locale changes at the model level. `test/screens/pomodoro_focus_room_static_test.dart` checks ranking widgets, selector structure, and timer isolation by source text. Neither mounts the two ranking sections with cached objects and proves that both selector builders repaint after a locale change without a `FocusRoomProvider` notification.

**Small retained transition:** Mount the room tab with one cached joined-room ranking and cached friends/global rankings while the locale is Chinese. Include a local multi-reason flagged entry and a remote entry with a nonempty literal `riskSummary` (ideally equal to a Chinese local phrase), plus an empty-summary remote fallback if practical. Record ranks, scores, order, room ID, and object identity. Change only `I18n` to English and pump; assert both selector sections repaint, social headings/subtitles and the local flag tooltip change language, while the literal remote summary and all numeric/order data stay fixed. Switch back to Chinese. This specifically catches dynamic-getter equality false negatives; a model-only `flagReasonFor` assertion does not.
