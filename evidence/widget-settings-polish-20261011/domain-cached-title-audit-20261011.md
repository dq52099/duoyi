# Cached diary and note titles — follow-up audit (2026-10-11)

Read-only source audit. This narrows the [domain model locale contract](domain-model-locale-contract-20261011.md) to titles copied into calendar events and global search hits. No source or tests were changed or run.

## Finding: a translated model getter does not update an existing cache

`CalendarAggregator._diaryEvents` copies `d.title` into `CalendarEvent.title` (`lib/core/calendar_aggregator.dart:350-369`). `CalendarProvider.rebuild` retains events while its input signature is unchanged (`lib/providers/calendar_provider.dart:220-267,300-325`); the calendar screen's locale listener calls `setState`, but locale is absent from its rebuild input signature (`lib/screens/calendar_screen.dart:88-94,125-165,190-213`). The existing `DiaryDisplayMetadata` holds only a required mood key, and is omitted when mood is null (`lib/models/calendar_event.dart:263-266`; `lib/core/calendar_aggregator.dart:362-374`). Thus a locale-aware `DiaryEntry.title` alone leaves an already aggregated empty diary title in its old language, especially an empty diary without mood.

`GlobalSearch.run` likewise copies `n.title` and `d.title` into final `SearchHit.title` fields (`lib/core/global_search.dart:28-45,126-153`). `SearchScreen` stores the hit list in `_hits` after the query and renders `h.title`; it has no locale listener or locale dependency of its own (`lib/screens/search_screen.dart:36-91,211-276,303-390`). Changing the model getter does not mutate those hits.

## Minimum runtime provenance

| Cache | Proposed marker and resolver | Boundary |
| --- | --- | --- |
| Calendar diary event | Extend `DiaryDisplayMetadata` with nullable `fallbackTitleDate`, and make `moodKey` nullable. Construct metadata when **either** mood exists **or** `d.content.trim().isEmpty`. Set `fallbackTitleDate` only for the latter, using `d.date`. In `CalendarEventDisplayText.resolveTitle`, format that date in the selected locale through the same fallback formatter used by `DiaryEntry.titleFor(locale)`; otherwise return `event.title`. In `resolveSubtitle`, translate only a non-null `moodKey`, otherwise return `event.subtitle`. | A mood and a generated title are independent. In particular, an empty diary with no mood needs title metadata, while a nonempty diary with mood needs only subtitle metadata. Do not infer provenance by comparing cached text to `M月D日的日记` or by relying on `event.type` alone. |
| Search note/diary hit | Add one optional typed value, for example `SearchGeneratedTitleKind? generatedTitleKind` with `emptyNote` and `emptyDiary`; null means the cached `title` is literal. Set it from `n.content.trim().isEmpty` or `d.content.trim().isEmpty` when creating a hit. `SearchHit.titleFor(AppLocale locale)` (or a live `displayTitle` getter) resolves only marked hits. The existing `when` value already carries `d.date` for diary hits; a diary marker must only be used when that date is present. Preserve `title` for callers expecting the original snapshot. | Render the resolved title in `SearchScreen._resultCard` and subscribe the screen to locale changes so stored hits repaint. There is no need to rerun the query solely to translate a matched hit. |

The provenance test is **empty authored content**, not whether the current title equals a translated fallback string. A user may write exactly `无标题笔记`, `10月11日的日记`, or the English equivalent as their first line; those strings remain literal across locales. Model JSON stores the authored content and diary date, not derived titles (`lib/models/note.dart:200-211`; `lib/models/diary_entry.dart:103-127`).

## Consumers and compatibility edges

- `CalendarEventDisplayText.resolveTitle` is presently used by `CalendarEventSheet`, which already rebuilds through `I18n.localeListenable` (`lib/widgets/calendar_event_sheet.dart:427-437`). The calendar's compact/day rows and week list still paint raw `e.title` / `event.title` (`lib/widgets/calendar_day_agenda.dart:675,744`; `lib/widgets/calendar_week_strip.dart:468`). They must call the resolver too; otherwise only the sheet changes language. The week list also uses raw title as a tie breaker (`calendar_week_strip.dart:226-233`); decide whether visual order should follow displayed titles, then apply the same choice consistently.
- `CalendarEvent.toJson` and `fromJson` intentionally omit `displayMetadata` (`lib/models/calendar_event.dart:118-176`). This recommendation is runtime-only: a JSON round trip preserves the cached literal title and gains no generated-title inference. Persisted local and imported ICS events remain literal. Do not introduce an unversioned serialized marker as part of this narrow change.
- Search matching currently uses note `content`, and diary `content` or tags; it does not search generated titles (`lib/core/global_search.dart:126-153`). In particular, an empty note cannot currently produce a hit, while an empty diary can match its tags. Preserve this matching contract and `maxPerKind` behavior; a title marker affects display only. Calendar-event search filters to `CalendarEventType.event`, so diary calendar events are not separately duplicated as search hits (`global_search.dart:217-240`).
- CSV, widget snapshot, and Chinese AI prompt contracts remain as recorded in the earlier audit. This follow-up only addresses in-memory calendar and search display caches.

## Acceptance targets for the owner

1. Build an empty diary calendar event without mood in Chinese, switch to English without rebuilding the event object, and observe an English title in the event sheet, compact/day agenda, and week list. A mood-bearing empty diary changes both title and mood subtitle; an authored first line remains exact even if it equals a fallback phrase.
2. Keep existing search hits on screen across a locale switch. A tag-matched empty diary changes its displayed title while its `title` snapshot, source ID, query membership, and navigation date remain unchanged. An authored note/diary title stays literal. The empty-note marker can be exercised through a directly constructed `SearchHit` because current query matching excludes empty notes.
3. Confirm legacy calendar JSON round trips still have null metadata and literal titles. Existing targets are `test/core/calendar_event_display_text_test.dart` and `test/core/global_search_time_entry_test.dart`; the locale screen behavior belongs in a focused widget test alongside `test/screens/calendar_content_locale_state_test.dart`.

## Decision follow-up: central `title` getters (2026-10-11)

**Recommendation:** keep `CalendarEvent.title` as stored data and use the typed `DiaryDisplayMetadata.fallbackTitleDate` through `CalendarEventDisplayText.resolveTitle` in the calendar UI. Ask the frontend owner to use the resolver in the compact/day/week rows. A private `_title` plus live public getter would repair those rows without touching them, but it changes `title` for several non-UI callers and is not the minimum safe calendar change.

The concrete issue is broader than `CalendarEvent.toJson`. Its current `copyWith` defaults to `this.title` (`lib/models/calendar_event.dart:93-126`), so a live getter would freeze the currently selected language into a copied event unless the default is changed to raw `_title`. Conflict tagging uses `copyWith` on aggregated events (`lib/core/calendar_aggregator.dart:420-430`), and `CalendarProvider._asLocalEvent` uses it while changing the type to a persisted local event (`lib/providers/calendar_provider.dart:180-189`). That conversion currently retains `displayMetadata`; with a getter based on metadata alone, a converted local event could continue changing title by locale until reload. A type guard and explicit metadata clearing on type conversion would be needed. An explicit `copyWith(title: authoredText)` must clear only the diary fallback marker, retaining any mood key, unless the caller explicitly supplies replacement metadata.

Even if `CalendarEvent.toJson` writes raw `_title`, other data paths read public `event.title`: provider event hashes and equality (`lib/providers/calendar_provider.dart:508-565`), import validation/duplicate keys (`:78-98,718-726`), and CalDAV summary plus a separate calendar JSON helper (`lib/services/calendar_sync_service.dart:831-855,1156-1165`). A lazy getter would make those values locale-dependent unless each path is reviewed and deliberately switched to raw storage. `CalendarEvent.fromJson` has no metadata, so the same object would behave differently before and after a JSON round trip. These consequences make a central getter a wider contract change than the calendar display fix.

`SearchHit` is different: it is an ephemeral result object with no `copyWith` or serialization; its consumers are the search screen. A private raw field plus a const-compatible named constructor and a public live `title` getter is a reasonable minimal option there, provided provenance is a nullable sealed value such as `emptyNote` or `emptyDiary(date)` and null returns raw text. The diary date belongs in the provenance rather than depending on `when`, whose separate purpose is result date/navigation. `GlobalSearch.run` should continue matching authored content/tags and constructing the same IDs. The search screen still needs a locale listener or equivalent dependency to repaint its retained `_hits`; a lazy getter alone does not schedule a frame.
